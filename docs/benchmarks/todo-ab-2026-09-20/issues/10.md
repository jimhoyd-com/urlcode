**Tried:** use URLCode's existing UI capabilities for the list/form interface.

**Got:** `@jimhoyd/urlcode-ui` needs operator host wiring (run 2), and neither run found a data-bound list/form component, so both hand-wrote HTML plus 52-64 lines of browser JS. Both UI scripts had defects (edit text lost on re-render; a failed update left the checkbox flipped). Related: #217 (closed) covers UI wiring in auth/admin scaffolds only.
**Suggestion:** a documented path (and starter) for a plain project to serve a UI-kit page, and a small data-bound list/form pattern for CRUD screens.
**Evidence:** an A/B benchmark on URLCode 0.4.1 with Sonnet 5 agents building the same Todo app from the repo docs. Run 1 (benchmark Agent B, no authoring skill, no browser check) and run 2 (session "Todo application with URLCode", authoring skill loaded, tightened prompt) hit this independently. n=1 each; single small app, so treat frequency as anecdotal. The Agent A control (no URLCode) needed 2 shell calls and 0 dependencies for the same app.
