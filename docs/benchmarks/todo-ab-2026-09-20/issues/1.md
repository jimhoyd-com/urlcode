**Tried:** persist todos across restarts using only declared URLCode features.
**Expected:** a declarative store/collection handler, or at minimum a recipe for file-backed CRUD.
**Got:** neither exists (`recipes search "crud store persist"` returns nothing; docs list a guest storage broker as unavailable). Both runs hand-wrote a JSON-file store inside a trusted function (queue + atomic rename): about 26-40 lines each, inside 112-116 LOC of custom backend JS. That is why 63-64% of application code stayed imperative.
**Suggestion:** a `store:`/collection handler (list/get/create/patch/delete, id + createdAt/updatedAt, file- or SQLite-backed) or an extension, plus a `crud-todo` recipe. Related: #133 (read-through data binding, closed).
**Evidence:** an A/B benchmark on URLCode 0.4.1 with Sonnet 5 agents building the same Todo app from the repo docs. Run 1 (benchmark Agent B, no authoring skill, no browser check) and run 2 (session "Todo application with URLCode", authoring skill loaded, tightened prompt) hit this independently. n=1 each; single small app, so treat frequency as anecdotal. The Agent A control (no URLCode) needed 2 shell calls and 0 dependencies for the same app.
**Not verified:** how much of the custom code a store handler would remove for apps beyond a Todo list.
