**Tried:** map GET/POST/PUT/PATCH/DELETE on `/api/todos/{id}` to distinct logic.
**Expected:** per-method handlers, and path parameters auto-declared regardless of form.
**Got:** one function per route; both runs branch on `request.method` inside the function and split by path with named exports. Using `export:` forces the long form, where the path `id` parameter and `args` must be re-declared by hand (the short form auto-binds them). Nothing in the docs states this trade-off.
**Suggestion:** `methods: {GET: {function: ...}, POST: {...}}`, and auto-declare/auto-bind path parameters in the long form (or document the rule next to `export:`).
**Evidence:** an A/B benchmark on URLCode 0.4.1 with Sonnet 5 agents building the same Todo app from the repo docs. Run 1 (benchmark Agent B, no authoring skill, no browser check) and run 2 (session "Todo application with URLCode", authoring skill loaded, tightened prompt) hit this independently. n=1 each; single small app, so treat frequency as anecdotal. The Agent A control (no URLCode) needed 2 shell calls and 0 dependencies for the same app.
