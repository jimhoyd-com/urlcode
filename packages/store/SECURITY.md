# Security boundary

The store is trusted operator code. It runs in the host process, is not sandboxed and is not a multi-tenant boundary. Every caller who can reach a mount can read and (unless `readOnly`) change every record in that collection, so protect mounts with the auth extension or another policy and never put one user's private data in a collection another user can reach.

The data directory belongs to the operator: keep it outside the project, on local disk, readable only by the server user. The store creates it `0700` and its files `0600`, takes an exclusive lock and supports one server process per directory. Do not share it over a network filesystem. Protect backups like the data itself.

The directory lock file holds `<pid>:<instance>` (an instance id generated once per process start), written atomically (a uniquely-named temporary file, then linked into place, so no reader can ever see an empty or partial lock file). A lock bearing our own PID but a different instance id is treated as stale and reclaimed rather than as this process already holding it — a container restarted after an unclean exit routinely gets the same PID back (often PID 1), and without this, that restart would refuse to start until an operator removed the lock file by hand.

Requests are bounded (body, record, page and quota limits), validated against the declared field schema, and JSON-only for writes with a same-origin check on the `Origin` header. Errors return fixed messages and field names; they never echo submitted values, file contents or paths. Passing tests do not establish independent assessment or behavior under crash or disk-full conditions on every filesystem.

A single-record `GET`/`HEAD` returns a strong `ETag`; `PUT`, `PATCH` and `DELETE` honour an `If-Match` header carrying it and refuse with `412` when it no longer matches the record's current state, so a caller can avoid silently clobbering a concurrent writer's change. `If-Match` is optional — a write that omits it stays last-write-wins, unchanged from before. A short-link mount's declared destination field must be `required`; a record without it (only possible from data written before that requirement existed) resolves to `404` without counting a click rather than a `302` to `Location: undefined`, and `HEAD` never counts a click either way. `Idempotency-Key` retention is scoped per network client (hashed together with the header value into one opaque key), so two callers who happen to choose the same key do not collide; an unauthenticated mount has no stronger caller identity than the network client to scope by.

This package follows the [core URLCode security policy](../../SECURITY.md) for reporting. Never post real data or credentials in public issues.
